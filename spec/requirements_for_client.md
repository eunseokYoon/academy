## 1. 서비스 개요

영어 강사 1인이 운영하는 학원의 **학생·학부모 관리 시스템**입니다. 선생님이 수업·출석·숙제·성적을 한 번 입력하면 학생과 학부모가 각자의 화면에서 확인합니다.

### 운영 규모 (전제)

| 항목 | 수량 |
|---|---|
| 강사 | 1명 |
| 대상 학교 | 2개교 |
| 학년 | 각 학교 1~3학년 (총 6개 코호트) |
| 학생 | 약 200명 |

이 규모를 전제로 설계했습니다. **학생 수가 크게 늘거나 강사가 추가되면 별도 협의가 필요합니다.**

### 계정 구조

- 학부모 1명이 자녀 여러 명을 볼 수 있습니다 (형제·자매).
- 학생 1명에게는 학부모 계정 1개가 연결됩니다.
- **누구나 가입할 수는 없습니다.** 선생님이 학생을 등록하면 회원가입 코드 2장(학생용·학부모용)이 발급되고, 학생과 학부모가 **각자** 그 코드와 본인 전화번호로 회원가입합니다.
- **로그인 아이디는 전화번호입니다.** 별도 아이디를 만들지 않습니다.
- **초기 비밀번호는 `0000`이며, 로그인 후 본인이 자유롭게 변경합니다.** 비밀번호를 바꾸기 전에는 다른 화면에 들어갈 수 없도록 막습니다. 초기 비밀번호는 누구나 아는 값이라, 이 장치가 없으면 남의 성적·피드백이 노출됩니다.
- **학생과 학부모는 서로 다른 전화번호가 필요합니다.** 같은 번호로 두 계정을 만들 수 없습니다. 학생이 본인 휴대폰이 없으면 등록이 불가하므로 **사전 확인이 필요합니다.**
- 비밀번호를 잊으면 **선생님이 관리자 화면에서 초기화**합니다. 문자·이메일 자동 발송은 1차 범위 밖입니다.

> **P-4가 학부모 화면의 핵심입니다.** 자녀의 단어 테스트 성적 흐름을 한눈에 보는 것이 목적이므로, 표가 아니라 그래프가 먼저 나와야 합니다.

### 2-5. 클리닉이란

정규 수업과 별개로 진행하는 **보충 수업**입니다. **정해진 시간대에 여러 학생이 함께** 참여합니다.

```
선생님이 클리닉 시간대를 열어 둠 (T-13)
  ├─ 학생이 직접 신청 (S-9)
  └─ 또는 선생님이 학생을 배정 (T-13)
  → 학생이 시간 변경을 요청 (사유 선택 필수) → 선생님이 승인·거절 (T-13)
  → 당일 선생님이 출석 체크 (T-13)
  → 학부모는 자녀의 클리닉 일정과 출석 여부를 확인 (P-2)
```

**신청 경로가 두 가지입니다.** 학생이 직접 신청할 수도, 선생님이 배정할 수도 있습니다.

**시간 변경은 학생이 요청하고 선생님이 승인합니다.** 학생이 임의로 바꿀 수 없습니다.
요청 시 **변경 사유를 목록에서 선택**해야 합니다.

> ⚠️ **변경 사유 옵션 목록이 미확정입니다.** 학원장이 정해 주셔야 합니다 (아래 4-6).

### 4-1. 알림 발송 수단

웹 단계에서는 학부모·학생에게 능동적으로 알림을 보낼 수단이 없습니다. 로그인해서 확인하는 구조입니다.

| 선택지 | 비용 | 비고 |
|---|---|---|
| 알림 없음 (1차 기본안) | 없음 | 앱 출시 시 푸시로 해결 |
| 카카오 알림톡 | 건당 과금 + 템플릿 사전 승인 필요 | 발송 건수 추정 필요 |
| SMS | 건당 과금 | 알림톡보다 단가 높음 |

**결정 사항:** ☐ 알림 없음  ☐ 알림톡 도입 (월 예상 발송량: ______건)

### 4-2. 결제 기능

수강료 결제를 시스템에 포함할지 결정이 필요합니다. 포함 시 PG사 계약, 정산, 환불 정책이 함께 정의되어야 하며 개발 범위가 크게 늘어납니다.

**결정 사항:** ☐ 미포함

### 4-3. 수업 영상 호스팅 방식

| 선택지 | 비용 | 비고 |
|---|---|---|
| YouTube 미등록(unlisted) 링크 | 없음 | 링크 유출 시 외부 시청 가능 |
| Vimeo 등 유료 호스팅 | 월 정액 | 도메인 제한 등 보호 기능 있음 |
| 자체 서버 저장 | 전송량 과금 | 200명 시청 시 비용 부담 큼 |

**결정 사항:** ☐ YouTube  ☐ 유료 호스팅  ☐ 자체 저장

### 4-4. 제출 사진 보관 기간

학생 숙제 사진은 연간 5~8만 장이 누적됩니다. 무기한 보관 시 저장 비용이 계속 증가합니다.

**결정 사항:** 보관 기간 ______개월 이후 자동 삭제 (권장: 12개월)

### 4-5. 성적 관리 범위

내신 성적과 모의고사 성적 중 어디까지 시스템에 입력할지, 영어 외 과목도 입력하는지 확정이 필요합니다.

**결정 사항:** ☐ 영어만  ☐ 전 과목

## 5. 데이터 보호 관련 확인 사항

학생 이름, 학교, 학년, 연락처, 성적, 숙제 사진은 모두 개인정보입니다.

- 학부모는 **본인 자녀의 정보만** 조회할 수 있도록 서버에서 권한을 검증합니다.
- 학생은 본인 정보만 조회할 수 있으며, 다른 학생의 성적·숙제는 볼 수 없습니다.
- 미성년자 정보를 다루므로 **법정대리인 동의 절차**와 개인정보처리방침 게시가 필요합니다. 방침 문안은 학원 측에서 제공하거나 별도 검토가 필요합니다.
- 퇴원생 데이터의 보관·삭제 기준을 정해야 합니다.

> ⚠️ **아래 두 항목은 현재 어느 개발 단계에도 포함되어 있지 않습니다.**
> 화면·기능이 정의되지 않아 그대로 두면 미구현 상태로 오픈합니다.

**5-1. 법정대리인 동의 절차**

현재 개발 범위에는 약관·개인정보처리방침을 **게시하는 화면(C-3)만** 있습니다.
동의를 받아 기록으로 남기는 절차는 없습니다.

| 선택지 | 개발 영향 |
|---|---|
| 회원가입 시 동의 체크 + 동의 시각 저장 | 컬럼 2개 + 가입 화면 체크박스 (소) |
| 종이 동의서로 오프라인 수령 | 개발 없음. 학원이 보관 책임 |
| 별도 동의 화면·이력 관리 | 화면 1개 + 테이블 1개 추가 (중) |

**결정 사항:** ☐ 가입 시 체크 ☐ 오프라인 수령 ☐ 별도 화면

**5-2. 퇴원생 데이터 보관 기간**

현재는 **무기한 보관**입니다. 퇴원 처리해도 출석·성적·숙제 사진이 그대로 남습니다.
재등록과 통계를 위한 설계이지만, 보관 기간을 정하지 않으면 개인정보를 무기한 보유하게 됩니다.

**결정 사항:** 퇴원 후 데이터 보관 기간 ______개월 (권장: 12개월, 이후 자동 삭제)

## 부록. 기술 구성

|---|---|
